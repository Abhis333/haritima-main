# Internationalization (English / Hindi)

The UI can be shown in English (`en`) or Hindi (`hi`). The choice is stored in the `haritima-lang` cookie.

## Files
- `lib/i18n/dictionaries.ts`: the `Lang` type, `LANG_COOKIE`, and the `en` and `hi` dictionaries of UI strings, grouped by section (`nav`, `hero`, `home`, `plant`, `mantras`, …).
- `lib/i18n/server.ts` (server-only): `getLang()` and `getDictionary()`, which returns `{ lang, t }`.
- `lib/i18n/client.tsx`: `LanguageProvider` and the `useLang()` hook for client components.
- `lib/i18n/pick.ts`: `pick(lang, en, hi)` returns the Hindi value when the UI is Hindi and a translation exists, and falls back to English otherwise. It works on both server and client.
- `components/LanguageSwitcher.tsx`: sets the cookie.

## Two layers of translation
1. **UI strings** live in the dictionaries. Every new string must be added to both `en` and `hi`.
2. **Database content** uses parallel `*Hi` columns: `descriptionHi`, `traditionalUsesHi[]`, `concernHi`, `nameHi` on categories, `hindiName`, and `hindiTranslation` on mantras. Show them with `pick()`, or with an explicit `lang === "hi" && x ? x : fallback` check, as `lib/map-data.ts` and `lib/chat.ts` do.

## Notes
- The chatbot receives `lang`, answers in that language, and uses matching fixed texts (`DISCLAIMER`, `NO_MATCH`, `REF_NOT_AVAILABLE`, `URGENT`).
- The search tokenizer passes Devanagari words through unchanged, and `SYNONYMS` includes Hindi words, so Hindi queries also match.
